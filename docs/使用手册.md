# Farmos 使用手册（M1–M3.5）

面向编写 `.fm` 源文件的程序员。本文只描述规范已定稿的语言与标准库行为；未写明的细节一律不猜测。

---

## 1. Farmos 是什么

Farmos 是一门静态类型、表面语法接近 TypeScript 的编译型语言。源文件扩展名为 `.fm`，编译器命令为 `farmc`：它生成 C11，再调用系统上的 clang 或 gcc 链接成原生可执行文件（目标平台为 Windows x64）。标准库提供类似 Three.js 的数学类型（`farmos:math`）与场景图 / CPU 光栅化渲染 API（`farmos:scene`），适合把三维场景写成确定性程序并写出 PNG。

---

## 2. 最小程序与模块

### 2.1 Hello

入口文件必须恰好定义：

```
function main(): int {
  println("Hello, Farmos");
  return 0;
}
```

（摘自 `spec/tests/M1/001_hello.fm`。）`main` 无参数、返回类型必须是 `int`；返回值即进程退出码。其他模块不得再定义 `main`。

常用命令：

```
farmc build hello.fm [-o out.exe]
farmc run hello.fm
farmc version
farmc help
```

`farmc` 自身退出码：`0` 成功，`1` 编译错误，`2` 用法错误，`3` 驱动失败（缺 C 编译器等），`4` 内部错误。

### 2.2 模块怎么想

每个 `.fm` 文件是一个独立模块作用域。未 `export` 的顶层名字只在本文件可见；要在别的文件用，必须 `export`，再由对方 `import`。

相对路径导入（必须以 `.fm` 结尾）：

```
// math.fm
export function square(x: int): int {
  return x * x;
}
export const answer: int = 7;

// main.fm
import { square, answer } from "./math.fm";
```

（摘自 M1 多文件夹具。）导入解析相对导入方所在目录；环状导入报错。同名重复导入、导入未导出的名字、模块找不到，都会在编译期失败。

从 M2 起，内置模块用虚拟路径，不必以 `.fm` 结尾，例如 `"farmos:math"`、`"farmos:scene"`。它们不是磁盘路径。

## 3. M1 语言要点

### 3.1 类型与字面量

| 类型 | 含义 |
|------|------|
| `int` | 有符号 64 位整数（十进制或十六进制字面量，如 `42`、`0xff0000`） |
| `float` | IEEE 754 binary64（如 `1.0`、`1e3`；小数点两侧都要有数字，除非用指数形式） |
| `bool` | `true` / `false`，条件必须是 `bool`，无“真值”强制转换 |
| `string` | 不可变 UTF-8；`+` 拼接；`len(s)` 字节长度；无字符串下标 |
| `void` | 只能作函数/方法返回类型 |
| `T[N]` | 定长数组（值语义，赋值拷贝全部元素） |
| `T[]` | 动态数组；空字面量必须写成 `let a: int[] = [];` |
| `struct` | 值类型；赋值与传参拷贝字段 |
| `class` | 引用类型；`new` 分配，赋值拷贝引用；实例存活到进程结束（程序级 arena，无 GC） |

M1 下 `int` 与 `float` 运算不可隐式混用，需 `int(f)` / `float(i)`。整数溢出按二进制补码环绕；整数 `/` 或 `%` 除以零运行时陷阱退出码 **101**；浮点除以零遵循 IEEE（`Infinity` / `-Infinity` / `NaN`），不陷阱。数组越界陷阱 **102**；`int(非有限 float)` 陷阱 **103**。

标识符仅 ASCII；语句末尾分号必写，无自动插入。注释：`//` 与非嵌套 `/* */`。

### 3.2 绑定、控制流、函数

```
let x: int = 1;      // 可变
const y: int = 2;    // 绑定不可再赋；对 class 引用是浅 const（仍可改字段）
```

控制流：`if` / `else`、`while`、C/TS 风格 `for`、`break` / `continue`、`return`。`for` 的更新子句只能是赋值或调用。逻辑 `&&` / `||` 短路。

函数返回类型必写。非 `void` 必须在每条路径上 `return`。无闭包、无一等函数值、无用户泛型、无继承（用户代码）。

### 3.3 结构体与类

```
struct Point {
  x: int;
  y: int;
}

class Counter {
  n: int;
  constructor(n: int) {
    this.n = n;
  }
  inc(): void {
    this.n = this.n + 1;
  }
  get(): int {
    return this.n;
  }
}
```

（类示例摘自 `021_class_methods.fm`。）

- 结构体：`new Point(3, 4)`（按字段声明顺序）或 `Point { x: 3, y: 4 }`（每个字段恰好一次）。M1 结构体无方法（M2 起允许）。
- 类：只能 `new ClassName(args)`；必须恰好一个 `constructor`；方法里用 `this`。

### 3.4 数组与内置函数

```
let fixed: int[3] = [1, 2, 3];   // 裸字面量默认定长
let dyn: int[] = [1, 2];
push(dyn, 3);
println(len(dyn));
```

`print` / `println` 可打印 `int`/`float`/`bool`/`string`。浮点打印遵循 ECMAScript `Number::toString`，另有一条：`-0.0` 打印为 `-0`。

复合赋值 `+=` 等：左值子表达式只求值一次（例如 `a[f()] += 1` 只调用一次 `f`）。

### 3.5 常见编译错误码（用户常碰到的）

诊断格式：`路径:行:列: error[E0xxx]: 消息`（行列从 1 起算）。

| 码 | 典型含义 |
|----|----------|
| E0201 | 缺分号 |
| E0301–E0305 | 模块路径非法、环、重复导入、找不到模块、导入未导出的名字 |
| E0401 | 条件不是 `bool` |
| E0402 | `int`/`float` 混算且无显式转换（M1；M2 对**字面量**有放宽，见下章） |
| E0408 | 类型不匹配 |
| E0411 | 参数个数不对 |
| E0414 / E0416 / E0418 | 类构造相关 |
| E0504 | 给 `const` 再赋值 |
| E0505 | 未定义名字 |
| E0506 / E0507 | `main` 缺失或放错文件 |
| E0508 | 有路径未 `return` |
| E0510 | 循环外 `break`/`continue` |

完整表见 `spec/M1-core.md` §8.3；上表只列写程序时最常撞上的。

## 4. M2 数学库（`farmos:math`）

```
import { Vector3, Matrix4, Quaternion, Euler, Color } from "farmos:math";
```

数学类型全部是 **带方法的 `struct`（值类型）**。约定：右手坐标系、**Y 向上**、角度用**弧度**（Euler / 旋转矩阵等）；矩阵 `elements` 按列主序存储，`set(...)` 参数按行主序写入（与 Three.js 一致）。

### 4.1 整型字面量进浮点上下文（M2 起）

像 `new Vector3(1, 2, 3)`、`v.multiplyScalar(2)`、`1 + 2.0` 这类写法，在 M2+ 合法：出现在浮点参数、浮点赋值目标、或与另一侧为 `float` 的二元运算中的**整型字面量**（可带一元 `-`），若绝对值 ≤ 2⁵³ 且可精确表示为 binary64，则按 `float` 处理。非字面量的 `int` 表达式仍要 `float(i)`，否则仍是类型错误。超出精确表示范围的字面量报 **E0608**。

### 4.2 拷贝 vs 字段路径（重要）

```
let p: Vector3 = mesh.position;  // 拷贝
p.x = 1.0;                       // 改的是副本，mesh 不变
mesh.position.x = 1.0;           // 通过字段路径改对象内联存储
mesh.position.set(1.0, 2.0, 3.0);
```

（行为摘自 M2 §3.7 / M3 夹具 `010_position_copy_gotcha.fm`。）`const` 的结构体禁止改字段。

变异方法常 `return this`，在后缀链 `v.add(w).multiplyScalar(2.0)` 中共享同一接收者存储；结果逃逸到赋值等时再拷贝。

### 4.3 `Vector3`

字段：`x`/`y`/`z`。`new Vector3()` → `(0,0,0)`；`new Vector3(x,y,z)`。

常用方法（Y = 变异并返回自身类型）：`set`、`copy`、`clone`（纯）、`add` / `addVectors`、`sub` / `subVectors`、`multiplyScalar`、`divideScalar`（IEEE `/`）、`negate`、`dot`、`cross` / `crossVectors`、`length` / `lengthSq`、`normalize`（零向量保持不变）、`distanceTo`、`lerp`、`equals`、`applyMatrix3` / `applyMatrix4`、`applyQuaternion`、`transformDirection`、`projectOnVector`、`reflect`。

运算符（导入类型后可用）：`v+w`、`v-w`、`-v`、`v*s` / `s*v`、`v/s`、`v==w` / `v!=w`。**没有**向量 `%`。

```
import { Vector3 } from "farmos:math";

function main(): int {
  let v: Vector3 = new Vector3(1.0, 0.0, 0.0);
  v.add(new Vector3(0.0, 1.0, 0.0)).multiplyScalar(2.0);
  println(v);   // Vector3(2, 2, 0)
  return 0;
}
```

（摘自 `002_vector3_add_chain.fm`。）

同模块还有 `Vector2`、`Vector4`，方法模式类似；手册不逐条展开。

### 4.4 `Matrix4`

字段：`elements: float[16]`。`new Matrix4()` → 单位阵。

方法包括：`identity`、`set`（16 个行主序参数）、`copy`/`clone`、`multiply` / `premultiply` / `multiplyMatrices`、`multiplyScalar`、`determinant`、`transpose`、`invert`（奇异则置全零并仍返回 `this`）、`equals`、`makeTranslation` / `makeRotationX|Y|Z` / `makeScale`、`makePerspective`、`lookAt`、`compose`、`decompose`（三个参数为 in-out，必须传左值，否则 **E0607**）、`copyPosition`、`extractRotation`。

运算符：`m * m` → `Matrix4`；`m * Vector4` → `Vector4`；`m * Vector3` 按仿射点（`w=1`）变换。方向用 `transformDirection`。

另有 `Matrix3`（`elements: float[9]`），模式类似。

### 4.5 `Quaternion`

字段：`x,y,z,w`（`w` 为实部）。`new Quaternion()` → `(0,0,0,1)`。

方法：`set`/`copy`/`clone`、`identity`、`setFromEuler`、`setFromAxisAngle`、`setFromRotationMatrix`、`multiply` / `premultiply` / `multiplyQuaternions`、`normalize`（零长 → 单位四元数）、`invert`、`conjugate`、`dot`、`length` / `lengthSq`、`slerp`、`equals`。运算符：`q * q`。

### 4.6 `Euler`

字段：`x,y,z: float` 与 `order: string`。默认阶 **`"XYZ"`**。六种合法阶：

`"XYZ"`、`"YZX"`、`"ZXY"`、`"XZY"`、`"YXZ"`、`"ZYX"`。

非法阶在运行时陷阱退出码 **104**（`runtime error: invalid Euler order`）。方法：`set`、`copy`/`clone`、`setFromRotationMatrix`、`setFromQuaternion`、`reorder`、`equals`。

### 4.7 `Color`

字段：`r,g,b` 为线性浮点（惯例 [0,1]，可存出界值）。`new Color()`、`new Color(r,g,b)`、`new Color(hex: int)`（原始 `0xRRGGBB`，**无** sRGB↔线性转换）。`setHex` / `getHex`（量化前对通道 clamp，再用 `floor(c*255+0.5)`）。另有 `set`、`copy`/`clone`、`multiplyScalar`、`lerp`、`equals`。

### 4.8 打印与其它

`println`/`print`/`str` 对数学类型有固定格式，例如 `Vector3(1, 2, 3)`、`Color(r, g, b)`、`Euler(x, y, z, "XYZ")`（逗号后一个空格）。

同模块还导出 `Ray`、`Box3`、`Sphere`、`RayHit`（无 `null` 时用 `RayHit.hit` 表示是否命中）。用户可对自定义结构体重载 `+ - * / % == !=`（关键字 `operator`）；不可重载比较大小、逻辑与赋值运算符本身。

## 5. M3 场景库（`farmos:scene`）

```
import { Scene, PerspectiveCamera, BoxGeometry, MeshBasicMaterial,
         Mesh, Renderer } from "farmos:scene";
import { Color } from "farmos:math";
```

场景节点是 **class（引用）**；`position` / `rotation` / `quaternion` / `scale` 等数学字段以内联值形式存在对象里。`farmos:scene` **不**再导出数学类型，需要时自行从 `farmos:math` 导入。

### 5.1 最小渲染示例

```
function main(): int {
  const scene: Scene = new Scene();
  scene.setBackground(new Color(0x111111));

  const camera: PerspectiveCamera = new PerspectiveCamera(75, 1, 0.1, 1000);
  camera.position.z = 4;
  camera.lookAt(0, 0, 0);

  const geometry: BoxGeometry = new BoxGeometry(1, 1, 1);
  const material: MeshBasicMaterial = new MeshBasicMaterial(0x00ff88);
  const cube: Mesh = new Mesh(geometry, material);
  scene.add(cube);

  cube.rotation.x = 0.5;
  cube.rotation.y = 0.8;

  const renderer: Renderer = new Renderer(256, 256);
  renderer.render(scene, camera);
  renderer.savePNG("out.png");

  geometry.dispose();
  material.dispose();
  renderer.dispose();
  return 0;
}
```

（摘自 `003_rotating_cube.fm`；整型字面量在浮点处合法，见 §4.1。）

### 5.2 `Object3D` 与层次

字段默认：`position (0,0,0)`、`rotation (0,0,0,"XYZ")`、`quaternion (0,0,0,1)`、`scale (1,1,1)`、`matrixAutoUpdate true`、`visible true`。

层次 API：`add` / `remove` / `addAt` / `childCount` / `getChild`（无公开的 `children` 数组字段）。`add` 会先从旧父节点摘下；自环或成环 → 陷阱 **106**（`Object3D hierarchy cycle`）。`getChild` / 非法 `addAt` 下标 → **102**。

`rotation` 与 `quaternion` 双向同步：改一侧会更新另一侧（写 `rotation` → `setFromEuler`；写 `quaternion` → `setFromQuaternion` 并保留原 `order` 字符串）。六种 Euler 阶与 M2 相同。

`lookAt`：让局部 **-Z** 朝向目标，上方向 `(0,1,0)`，不改 `position`。`updateMatrix` 用 `compose(position, quaternion, scale)`；`renderer.render` 会 `updateMatrixWorld(true)`。

遍历：深度优先、前序、按子节点下标；`visible == false` 时整棵子树不画。

### 5.3 `Scene`

`Scene` 在标准库语义上可作为 `Object3D` 用（用户语言仍无 `extends`）。背景无 `null`，用：

- `hasBackground == false`（默认）：清屏黑色；
- `setBackground(color)` / `clearBackground()`。

### 5.4 几何、材质、网格

| 类型 | 说明 |
|------|------|
| `BoxGeometry` | `new BoxGeometry(w,h,d)` 或默认 `(1,1,1)`，原点居中 |
| `PlaneGeometry` | XY 平面朝 **+Z** |
| `SphereGeometry` | 半径 + 分段（过小分段会抬到最小合法值，不陷阱） |
| `MeshBasicMaterial` | 无光照，输出 `color`；忽略所有灯 |
| `MeshStandardMaterial` | `color` / `roughness`（默认 1）/ `metalness`（默认 0）；M3 为简化的 Lambert+Blinn 近似，**不是**完整 PBR |
| `Mesh` | `new Mesh(geometry, material)`，共享引用合法 |

几何与材质有 `dispose()`，释放原生 CPU 缓冲。

### 5.5 灯光

须挂在场景图上且 `visible`，才参与着色。

- `AmbientLight`：颜色 × 强度，无方向。
- `DirectionalLight`：默认局部 **-Z** 为光照“指向”；入射方向取世界方向的相反单位向量。
- `PointLight`：默认 `distance=0`、`decay=2`；衰减为逆平方，`distance > 0` 时超出则截止。

### 5.6 相机与渲染器

`new PerspectiveCamera(fov_degrees, aspect, near, far)`——**fov 是角度制**。`render` 会更新世界矩阵、逆矩阵，并调用 `updateProjectionMatrix`。

`Renderer`：`new Renderer(w,h)` 或稍后 `setSize`；`render(scene, camera)` 只填帧缓冲；`savePNG(path)` 写出上一帧。PNG 编码规范固定（仅 IHDR/IDAT/IEND、滤镜 None、zlib 压缩级别 0 等），便于字节级黄金图比对。

尺寸 ≤ 0 或超出实现支持范围 → 陷阱 **107**；写盘失败 → **108**。

### 5.7 陷阱 105 / 106（白话）

- **105 `use after dispose`**：对已 `dispose()` 的几何、材质或渲染器再走绘制 / `savePNG` 路径。第二次 `dispose()` 是空操作；只改 `mesh.position` 之类字段仍合法，真正画的时候才会炸。
- **106 `Object3D hierarchy cycle`**：`add` / `addAt` 会把节点挂到自己的祖先上，形成环。

长期循环里若不 `dispose`，原生缓冲会一直涨到进程结束（语言对象头仍由 arena 管到退出）。

### 5.8 场景相关编译码

除通用类型错误外，可能见到 **E0701**（不是几何类型）、**E0702**（不是材质类型）、**E0703**（`savePNG` 路径类型）等。优先仍用 M1 的 `E0408` / `E0411` 等能覆盖的情况。

## 6. M3.5 并发（`parallel` / `task`）

> M3.5 已有定稿规范与实现，并已合并进 master。下列语法与规则以 `spec/M3.5-concurrency.md` 为准。

### 6.1 语法与隐式汇合

```
function main(): int {
  let a: int = 0;
  let b: int = 0;
  parallel {
    task {
      a = fib(20);
    }
    task {
      b = fib(21);
    }
  }
  println(a + b);
  return 0;
}
```

（摘自 `001_two_tasks_basic.fm` 结构。）`parallel { ... }` 是语句，后面无分号。块内只能直接放一个或多个 `task { ... }`；至少 1 个、至多 **256** 个（第 257 个 → **E0807**）。`parallel` / `task` 是**上下文关键字**，在别处仍可当普通标识符。

语义：进入块时 fork，所有 task 跑完后 **隐式 join**，再执行后面的语句。任务体词法上可见外层局部变量 / 参数 / `this`，共享同一存储（不是拷贝闭包）；任务内声明的局部变量是任务私有的。任务无返回值，结果靠写入块外的位置。

### 6.2 输出顺序

任务里的 `print` / `println` 写入该任务的私有缓冲；join 时按 **源码中的任务编号 1..n** 依次刷到外层流。因此 stdout **不依赖调度**，即使慢任务排在前面编号，它的输出也仍然先出现（见夹具 `010_print_order.fm`）。

### 6.3 编译期冲突规则（必须按此记忆）

检测是**流不敏感**的：只要任务体文本里出现某次访问，就算写在 `if (false)` 里也会算上——即使运行时写从不重叠，仍可能报错。

| 情况 | 结果 |
|------|------|
| 两任务写同一位置，且两边都是**相同的静态常量** | 警告 **W0801**，仍编译成功（退出码 0），join 后该位置为该常量 |
| 两任务写同一位置，值不同，或任一侧不是可证常量（含未知） | 错误 **E0801** |
| 一任务读、另一任务写同一位置 | 错误 **E0802** |
| 两任务都只读 | 合法 |

复合赋值（`+=` 等）算作 **读 + 写**，且写入值视为未知 → 两任务对同一位置 `+=` 是 **E0801**（即使看起来都是 `+= 1`）。

`--werror`：把所有警告提升为错误（仍打印 `W0801` 这个码，但严重级别变成 `error`），不生成可执行文件，`farmc` 退出 1。

可能重叠（下标不静态、对象可能别名）在现行策略下与“确定重叠”同等对待：该报错就报错、该警告就警告（消息里可能带 “possibly / may”）。

### 6.4 任务里禁止的事

| 行为 | 码 |
|------|-----|
| 任务体内 `return` | E0803 |
| `break` / `continue` 跳出任务边界去命中外层循环 | E0804 |
| 调用带文件输出的 API（含 `savePNG`，经函数传递也算） | E0805 |
| 在 `parallel` 外写 `task { }` | E0806 |

`savePNG` 放在 join **之后**。任务内循环自己的 `break`/`continue` 没问题。

### 6.5 运行时线程数

环境变量 **`FARMOS_THREADS=<W>`**（`1 ≤ W ≤ 256`）由生成的程序在首次执行 `parallel` 时读取；非法或未设置则用默认（约 `min(任务数, 逻辑 CPU 数)`）。**不改变可观察结果**，只影响性能。`W=1` 时就是按任务编号顺序在单线程上跑完（顺序参考语义）。从未执行 `parallel` 的程序不会创建该变量、也不会拉线程库。

### 6.6 已知假阳性（简短）

冲突检查是保守的静态分析：它不能总是证明“两个 class 引用一定指向不同对象”，也不能通过 `let` 做常量传播（例如 `i`/`j` 运行时相等，仍可能把 `a[i]` 与 `a[j]` 当成可能重叠）。因此像“两个形参其实不会别名”这类程序可能被 **E0801** / **E0802** 误伤。规避方式是让互斥性可证明：不同 `new` 分配点、不同常量下标、可证明不交的计数循环区间、或各自写到不同字段 / 不同数组槽，再在 join 后合并。
