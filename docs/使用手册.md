# Farmos 使用手册（M1–M6）

面向编写 `.fm` 源文件的程序员。本文只描述规范已定稿的语言与标准库行为；未写明的细节一律不猜测。英文文档（`docs/language-reference.md` 等）对 M6 工程策略具有规范效力；本手册是中文信息性指南。

---

## 1. Farmos 是什么

Farmos 是一门静态类型、表面语法接近 TypeScript 的编译型语言。源文件扩展名为 `.fm`，编译器命令为 `farmc`：它生成 C11，再调用系统上的 clang 或 gcc 链接成原生可执行文件（目标平台为 Windows x64）。标准库提供类似 Three.js 的数学类型（`farmos:math`）、场景图 / CPU 光栅化与路径追踪（`farmos:scene`），以及刚体物理（`farmos:physics`）与浅水高度场（`farmos:liquid`），适合把三维场景写成确定性程序并写出 PNG / MP4。

## 2. 最小程序与模块

### 2.1 Hello

入口文件必须恰好定义：

```
function main(): int {
  println("Hello, Farmos");
  return 0;
}
```

（摘自 `spec/tests/M1/001_hello.fm`。）`main` 无参数、返回类型必须是 `int`；返回值即进程退出码。其他模块不得再定义 `main`。

常用命令：

```
farmc build hello.fm [-o out.exe]
farmc run hello.fm
farmc version
farmc help
```

`farmc` 自身退出码：`0` 成功，`1` 编译错误，`2` 用法错误，`3` 驱动失败（缺 C 编译器等），`4` 内部错误。

### 2.2 模块怎么想

每个 `.fm` 文件是一个独立模块作用域。未 `export` 的顶层名字只在本文件可见；要在别的文件用，必须 `export`，再由对方 `import`。

相对路径导入（必须以 `.fm` 结尾）：

```
// math.fm
export function square(x: int): int {
  return x * x;
}
export const answer: int = 7;

// main.fm
import { square, answer } from "./math.fm";
```

（摘自 M1 多文件夹具。）导入解析相对导入方所在目录；环状导入报错。同名重复导入、导入未导出的名字、模块找不到，都会在编译期失败。

从 M2 起，内置模块用虚拟路径，不必以 `.fm` 结尾，例如 `"farmos:math"`、`"farmos:scene"`。它们不是磁盘路径。

## 3. M1 语言要点

### 3.1 类型与字面量

| 类型 | 含义 |
|------|------|
| `int` | 有符号 64 位整数（十进制或十六进制字面量，如 `42`、`0xff0000`） |
| `float` | IEEE 754 binary64（如 `1.0`、`1e3`；小数点两侧都要有数字，除非用指数形式） |
| `bool` | `true` / `false`，条件必须是 `bool`，无“真值”强制转换 |
| `string` | 不可变 UTF-8；`+` 拼接；`len(s)` 字节长度；无字符串下标 |
| `void` | 只能作函数/方法返回类型 |
| `T[N]` | 定长数组（值语义，赋值拷贝全部元素） |
| `T[]` | 动态数组；空字面量必须写成 `let a: int[] = [];` |
| `struct` | 值类型；赋值与传参拷贝字段 |
| `class` | 引用类型；`new` 分配，赋值拷贝引用；实例存活到进程结束（程序级 arena，无 GC） |

M1 下 `int` 与 `float` 运算不可隐式混用，需 `int(f)` / `float(i)`。整数溢出按二进制补码环绕；整数 `/` 或 `%` 除以零运行时陷阱退出码 **101**；浮点除以零遵循 IEEE（`Infinity` / `-Infinity` / `NaN`），不陷阱。数组越界陷阱 **102**；`int(非有限 float)` 陷阱 **103**。

标识符仅 ASCII；语句末尾分号必写，无自动插入。注释：`//` 与非嵌套 `/* */`。

### 3.2 绑定、控制流、函数

```
let x: int = 1;      // 可变
const y: int = 2;    // 绑定不可再赋；对 class 引用是浅 const（仍可改字段）
```

控制流：`if` / `else`、`while`、C/TS 风格 `for`、`break` / `continue`、`return`。`for` 的更新子句只能是赋值或调用。逻辑 `&&` / `||` 短路。

函数返回类型必写。非 `void` 必须在每条路径上 `return`。无闭包、无一等函数值、无用户泛型、无继承（用户代码）。

### 3.3 结构体与类

```
struct Point {
  x: int;
  y: int;
}

class Counter {
  n: int;
  constructor(n: int) {
    this.n = n;
  }
  inc(): void {
    this.n = this.n + 1;
  }
  get(): int {
    return this.n;
  }
}
```

（类示例摘自 `021_class_methods.fm`。）

- 结构体：`new Point(3, 4)`（按字段声明顺序）或 `Point { x: 3, y: 4 }`（每个字段恰好一次）。M1 结构体无方法（M2 起允许）。
- 类：只能 `new ClassName(args)`；必须恰好一个 `constructor`；方法里用 `this`。

### 3.4 数组与内置函数

```
let fixed: int[3] = [1, 2, 3];   // 裸字面量默认定长
let dyn: int[] = [1, 2];
push(dyn, 3);
println(len(dyn));
```

`print` / `println` 可打印 `int`/`float`/`bool`/`string`。浮点打印遵循 ECMAScript `Number::toString`，另有一条：`-0.0` 打印为 `-0`。

复合赋值 `+=` 等：左值子表达式只求值一次（例如 `a[f()] += 1` 只调用一次 `f`）。

### 3.5 常见编译错误码（用户常碰到的）

诊断格式：`路径:行:列: error[E0xxx]: 消息`（行列从 1 起算）。

| 码 | 典型含义 |
|----|----------|
| E0201 | 缺分号 |
| E0301–E0305 | 模块路径非法、环、重复导入、找不到模块、导入未导出的名字 |
| E0401 | 条件不是 `bool` |
| E0402 | `int`/`float` 混算且无显式转换（M1；M2 对**字面量**有放宽，见下章） |
| E0408 | 类型不匹配 |
| E0411 | 参数个数不对 |
| E0414 / E0416 / E0418 | 类构造相关 |
| E0504 | 给 `const` 再赋值 |
| E0505 | 未定义名字 |
| E0506 / E0507 | `main` 缺失或放错文件 |
| E0508 | 有路径未 `return` |
| E0510 | 循环外 `break`/`continue` |

完整表见 `spec/M1-core.md` §8.3；上表只列写程序时最常撞上的。

## 4. M2 数学库（`farmos:math`）

```
import { Vector3, Matrix4, Quaternion, Euler, Color } from "farmos:math";
```

数学类型全部是 **带方法的 `struct`（值类型）**。约定：右手坐标系、**Y 向上**、角度用**弧度**（Euler / 旋转矩阵等）；矩阵 `elements` 按列主序存储，`set(...)` 参数按行主序写入（与 Three.js 一致）。

### 4.1 整型字面量进浮点上下文（M2 起）

像 `new Vector3(1, 2, 3)`、`v.multiplyScalar(2)`、`1 + 2.0` 这类写法，在 M2+ 合法：出现在浮点参数、浮点赋值目标、或与另一侧为 `float` 的二元运算中的**整型字面量**（可带一元 `-`），若绝对值 ≤ 2⁵³ 且可精确表示为 binary64，则按 `float` 处理。非字面量的 `int` 表达式仍要 `float(i)`，否则仍是类型错误。超出精确表示范围的字面量报 **E0608**。

### 4.2 拷贝 vs 字段路径（重要）

```
let p: Vector3 = mesh.position;  // 拷贝
p.x = 1.0;                       // 改的是副本，mesh 不变
mesh.position.x = 1.0;           // 通过字段路径改对象内联存储
mesh.position.set(1.0, 2.0, 3.0);
```

（行为摘自 M2 §3.7 / M3 夹具 `010_position_copy_gotcha.fm`。）`const` 的结构体禁止改字段。

变异方法常 `return this`，在后缀链 `v.add(w).multiplyScalar(2.0)` 中共享同一接收者存储；结果逃逸到赋值等时再拷贝。

### 4.3 `Vector3`

字段：`x`/`y`/`z`。`new Vector3()` → `(0,0,0)`；`new Vector3(x,y,z)`。

常用方法（Y = 变异并返回自身类型）：`set`、`copy`、`clone`（纯）、`add` / `addVectors`、`sub` / `subVectors`、`multiplyScalar`、`divideScalar`（IEEE `/`）、`negate`、`dot`、`cross` / `crossVectors`、`length` / `lengthSq`、`normalize`（零向量保持不变）、`distanceTo`、`lerp`、`equals`、`applyMatrix3` / `applyMatrix4`、`applyQuaternion`、`transformDirection`、`projectOnVector`、`reflect`。

运算符（导入类型后可用）：`v+w`、`v-w`、`-v`、`v*s` / `s*v`、`v/s`、`v==w` / `v!=w`。**没有**向量 `%`。

```
import { Vector3 } from "farmos:math";

function main(): int {
  let v: Vector3 = new Vector3(1.0, 0.0, 0.0);
  v.add(new Vector3(0.0, 1.0, 0.0)).multiplyScalar(2.0);
  println(v);   // Vector3(2, 2, 0)
  return 0;
}
```

（摘自 `002_vector3_add_chain.fm`。）

同模块还有 `Vector2`、`Vector4`，方法模式类似；手册不逐条展开。

### 4.4 `Matrix4`

字段：`elements: float[16]`。`new Matrix4()` → 单位阵。

方法包括：`identity`、`set`（16 个行主序参数）、`copy`/`clone`、`multiply` / `premultiply` / `multiplyMatrices`、`multiplyScalar`、`determinant`、`transpose`、`invert`（奇异则置全零并仍返回 `this`）、`equals`、`makeTranslation` / `makeRotationX|Y|Z` / `makeScale`、`makePerspective`、`lookAt`、`compose`、`decompose`（三个参数为 in-out，必须传左值，否则 **E0607**）、`copyPosition`、`extractRotation`。

运算符：`m * m` → `Matrix4`；`m * Vector4` → `Vector4`；`m * Vector3` 按仿射点（`w=1`）变换。方向用 `transformDirection`。

另有 `Matrix3`（`elements: float[9]`），模式类似。

### 4.5 `Quaternion`

字段：`x,y,z,w`（`w` 为实部）。`new Quaternion()` → `(0,0,0,1)`。

方法：`set`/`copy`/`clone`、`identity`、`setFromEuler`、`setFromAxisAngle`、`setFromRotationMatrix`、`multiply` / `premultiply` / `multiplyQuaternions`、`normalize`（零长 → 单位四元数）、`invert`、`conjugate`、`dot`、`length` / `lengthSq`、`slerp`、`equals`。运算符：`q * q`。

### 4.6 `Euler`

字段：`x,y,z: float` 与 `order: string`。默认阶 **`"XYZ"`**。六种合法阶：

`"XYZ"`、`"YZX"`、`"ZXY"`、`"XZY"`、`"YXZ"`、`"ZYX"`。

非法阶在运行时陷阱退出码 **104**（`runtime error: invalid Euler order`）。方法：`set`、`copy`/`clone`、`setFromRotationMatrix`、`setFromQuaternion`、`reorder`、`equals`。

### 4.7 `Color`

字段：`r,g,b` 为线性浮点（惯例 [0,1]，可存出界值）。`new Color()`、`new Color(r,g,b)`、`new Color(hex: int)`（原始 `0xRRGGBB`，**无** sRGB↔线性转换）。`setHex` / `getHex`（量化前对通道 clamp，再用 `floor(c*255+0.5)`）。另有 `set`、`copy`/`clone`、`multiplyScalar`、`lerp`、`equals`。

### 4.8 打印与其它

`println`/`print`/`str` 对数学类型有固定格式，例如 `Vector3(1, 2, 3)`、`Color(r, g, b)`、`Euler(x, y, z, "XYZ")`（逗号后一个空格）。

同模块还导出 `Ray`、`Box3`、`Sphere`、`RayHit`（无 `null` 时用 `RayHit.hit` 表示是否命中）。用户可对自定义结构体重载 `+ - * / % == !=`（关键字 `operator`）；不可重载比较大小、逻辑与赋值运算符本身。

## 5. M3 场景库（`farmos:scene`）

```
import { Scene, PerspectiveCamera, BoxGeometry, MeshBasicMaterial,
         Mesh, Renderer } from "farmos:scene";
import { Color } from "farmos:math";
```

场景节点是 **class（引用）**；`position` / `rotation` / `quaternion` / `scale` 等数学字段以内联值形式存在对象里。`farmos:scene` **不**再导出数学类型，需要时自行从 `farmos:math` 导入。

### 5.1 最小渲染示例

```
function main(): int {
  const scene: Scene = new Scene();
  scene.setBackground(new Color(0x111111));

  const camera: PerspectiveCamera = new PerspectiveCamera(75, 1, 0.1, 1000);
  camera.position.z = 4;
  camera.lookAt(0, 0, 0);

  const geometry: BoxGeometry = new BoxGeometry(1, 1, 1);
  const material: MeshBasicMaterial = new MeshBasicMaterial(0x00ff88);
  const cube: Mesh = new Mesh(geometry, material);
  scene.add(cube);

  cube.rotation.x = 0.5;
  cube.rotation.y = 0.8;

  const renderer: Renderer = new Renderer(256, 256);
  renderer.render(scene, camera);
  renderer.savePNG("out.png");

  geometry.dispose();
  material.dispose();
  renderer.dispose();
  return 0;
}
```

（摘自 `003_rotating_cube.fm`；整型字面量在浮点处合法，见 §4.1。）

### 5.2 `Object3D` 与层次

字段默认：`position (0,0,0)`、`rotation (0,0,0,"XYZ")`、`quaternion (0,0,0,1)`、`scale (1,1,1)`、`matrixAutoUpdate true`、`visible true`。

层次 API：`add` / `remove` / `addAt` / `childCount` / `getChild`（无公开的 `children` 数组字段）。`add` 会先从旧父节点摘下；自环或成环 → 陷阱 **106**（`Object3D hierarchy cycle`）。`getChild` / 非法 `addAt` 下标 → **102**。

`rotation` 与 `quaternion` 双向同步：改一侧会更新另一侧（写 `rotation` → `setFromEuler`；写 `quaternion` → `setFromQuaternion` 并保留原 `order` 字符串）。六种 Euler 阶与 M2 相同。

`lookAt`：让局部 **-Z** 朝向目标，上方向 `(0,1,0)`，不改 `position`。`updateMatrix` 用 `compose(position, quaternion, scale)`；`renderer.render` 会 `updateMatrixWorld(true)`。

遍历：深度优先、前序、按子节点下标；`visible == false` 时整棵子树不画。

### 5.3 `Scene`

`Scene` 在标准库语义上可作为 `Object3D` 用（用户语言仍无 `extends`）。背景无 `null`，用：

- `hasBackground == false`（默认）：清屏黑色；
- `setBackground(color)` / `clearBackground()`。

### 5.4 几何、材质、网格

| 类型 | 说明 |
|------|------|
| `BoxGeometry` | `new BoxGeometry(w,h,d)` 或默认 `(1,1,1)`，原点居中 |
| `PlaneGeometry` | XY 平面朝 **+Z** |
| `SphereGeometry` | 半径 + 分段（过小分段会抬到最小合法值，不陷阱） |
| `MeshBasicMaterial` | 无光照，输出 `color`；忽略所有灯 |
| `MeshStandardMaterial` | `color` / `roughness`（默认 1）/ `metalness`（默认 0）；M3 为简化的 Lambert+Blinn 近似，**不是**完整 PBR |
| `Mesh` | `new Mesh(geometry, material)`，共享引用合法 |

几何与材质有 `dispose()`，释放原生 CPU 缓冲。

### 5.5 灯光

须挂在场景图上且 `visible`，才参与着色。

- `AmbientLight`：颜色 × 强度，无方向。
- `DirectionalLight`：默认局部 **-Z** 为光照“指向”；入射方向取世界方向的相反单位向量。
- `PointLight`：默认 `distance=0`、`decay=2`；衰减为逆平方，`distance > 0` 时超出则截止。

### 5.6 相机与渲染器

`new PerspectiveCamera(fov_degrees, aspect, near, far)`——**fov 是角度制**。`render` 会更新世界矩阵、逆矩阵，并调用 `updateProjectionMatrix`。

`Renderer`：`new Renderer(w,h)` 或稍后 `setSize`；`render(scene, camera)` 只填帧缓冲；`savePNG(path)` 写出上一帧。PNG 编码规范固定（仅 IHDR/IDAT/IEND、滤镜 None、zlib 压缩级别 0 等），便于字节级黄金图比对。

尺寸 ≤ 0 或超出实现支持范围 → 陷阱 **107**；写盘失败 → **108**。

### 5.7 陷阱 105 / 106（白话）

- **105 `use after dispose`**：对已 `dispose()` 的几何、材质或渲染器再走绘制 / `savePNG` 路径。第二次 `dispose()` 是空操作；只改 `mesh.position` 之类字段仍合法，真正画的时候才会炸。
- **106 `Object3D hierarchy cycle`**：`add` / `addAt` 会把节点挂到自己的祖先上，形成环。

长期循环里若不 `dispose`，原生缓冲会一直涨到进程结束（语言对象头仍由 arena 管到退出）。

### 5.8 场景相关编译码

除通用类型错误外，可能见到 **E0701**（不是几何类型）、**E0702**（不是材质类型）、**E0703**（`savePNG` 路径类型）等。优先仍用 M1 的 `E0408` / `E0411` 等能覆盖的情况。

## 6. M3.5 并发（`parallel` / `task`）

> M3.5 已有定稿规范与实现，并已合并进 master。下列语法与规则以 `spec/M3.5-concurrency.md` 为准。

### 6.1 语法与隐式汇合

```
function main(): int {
  let a: int = 0;
  let b: int = 0;
  parallel {
    task {
      a = fib(20);
    }
    task {
      b = fib(21);
    }
  }
  println(a + b);
  return 0;
}
```

（摘自 `001_two_tasks_basic.fm` 结构。）`parallel { ... }` 是语句，后面无分号。块内只能直接放一个或多个 `task { ... }`；至少 1 个、至多 **256** 个（第 257 个 → **E0807**）。`parallel` / `task` 是**上下文关键字**，在别处仍可当普通标识符。

语义：进入块时 fork，所有 task 跑完后 **隐式 join**，再执行后面的语句。任务体词法上可见外层局部变量 / 参数 / `this`，共享同一存储（不是拷贝闭包）；任务内声明的局部变量是任务私有的。任务无返回值，结果靠写入块外的位置。

### 6.2 输出顺序

任务里的 `print` / `println` 写入该任务的私有缓冲；join 时按 **源码中的任务编号 1..n** 依次刷到外层流。因此 stdout **不依赖调度**，即使慢任务排在前面编号，它的输出也仍然先出现（见夹具 `010_print_order.fm`）。

### 6.3 编译期冲突规则（必须按此记忆）

检测是**流不敏感**的：只要任务体文本里出现某次访问，就算写在 `if (false)` 里也会算上——即使运行时写从不重叠，仍可能报错。

| 情况 | 结果 |
|------|------|
| 两任务写同一位置，且两边都是**相同的静态常量** | 警告 **W0801**，仍编译成功（退出码 0），join 后该位置为该常量 |
| 两任务写同一位置，值不同，或任一侧不是可证常量（含未知） | 错误 **E0801** |
| 一任务读、另一任务写同一位置 | 错误 **E0802** |
| 两任务都只读 | 合法 |

复合赋值（`+=` 等）算作 **读 + 写**，且写入值视为未知 → 两任务对同一位置 `+=` 是 **E0801**（即使看起来都是 `+= 1`）。

`--werror`：把所有警告提升为错误（仍打印 `W0801` 这个码，但严重级别变成 `error`），不生成可执行文件，`farmc` 退出 1。

可能重叠（下标不静态、对象可能别名）在现行策略下与“确定重叠”同等对待：该报错就报错、该警告就警告（消息里可能带 “possibly / may”）。

### 6.4 任务里禁止的事

| 行为 | 码 |
|------|-----|
| 任务体内 `return` | E0803 |
| `break` / `continue` 跳出任务边界去命中外层循环 | E0804 |
| 调用带文件输出的 API（含 `savePNG`，经函数传递也算） | E0805 |
| 在 `parallel` 外写 `task { }` | E0806 |

`savePNG` 放在 join **之后**。任务内循环自己的 `break`/`continue` 没问题。

### 6.5 运行时线程数

环境变量 **`FARMOS_THREADS=<W>`**（`1 ≤ W ≤ 256`）由生成的程序在首次执行 `parallel` 时读取；非法或未设置则用默认（约 `min(任务数, 逻辑 CPU 数)`）。**不改变可观察结果**，只影响性能。`W=1` 时就是按任务编号顺序在单线程上跑完（顺序参考语义）。从未执行 `parallel` 的程序不会创建该变量、也不会拉线程库。

### 6.6 已知假阳性（简短）

冲突检查是保守的静态分析：它不能总是证明“两个 class 引用一定指向不同对象”，也不能通过 `let` 做常量传播（例如 `i`/`j` 运行时相等，仍可能把 `a[i]` 与 `a[j]` 当成可能重叠）。因此像“两个形参其实不会别名”这类程序可能被 **E0801** / **E0802** 误伤。规避方式是让互斥性可证明：不同 `new` 分配点、不同常量下标、可证明不交的计数循环区间、或各自写到不同字段 / 不同数组槽，再在 join 后合并。

## 7. M4 路径追踪（`farmos:scene` 扩展）

M4 在现有 `Renderer` 上增加确定性前向路径追踪，并扩展材质与灯光。规范见 `spec/M4-ray.md`。

### 7.1 `render` 与 `renderPath`

| API | 作用 |
|-----|------|
| `renderer.render(scene, camera)` | M3 CPU 光栅化；像素与已发布的 M3 黄金图**字节级一致** |
| `renderer.renderPath(scene, camera)` | M4 路径追踪；写入累加器均值后再量化到显示缓冲 |

光栅化 **`render` 忽略**（不读、不参与着色）：`transmission` / `ior` / `emissive` / `emissiveIntensity`、`Texture` / `setMap`、以及所有 `RectAreaLight`。`render` 也不碰路径追踪累加器；`renderPath` 不跑光栅化、不写深度缓冲。

`savePNG` 写出**最近一次** `render` 或 `renderPath` 留下的显示缓冲（PNG 编码规则同 M3）。

### 7.2 新增 API 与累加

```
setSamples(n: int): void          // 默认 1
setMaxBounces(n: int): void       // 默认 4
resetAccumulation(): void
renderPath(scene: Scene, camera: PerspectiveCamera): void
```

- 一次 `renderPath` 给每个像素**追加**恰好 `samples` 个新样本，再把均值量化到显示缓冲（clamp 到 [0,1]，`floor(c*255+0.5)`）。
- `resetAccumulation()` 把累加器与样本计数清零；本身不改写显示缓冲。下次 `renderPath` 从全局样本下标 0 重新开始。
- `setSize` 会分配显示缓冲 + float64 RGB 累加器，并清零计数与显示缓冲（光栅深度缓冲仍按 M3）。

```
const renderer: Renderer = new Renderer(32, 32);
renderer.setSamples(4);
renderer.setMaxBounces(3);
renderer.renderPath(scene, camera);
renderer.savePNG("out.png");
```

（结构摘自 `009_glass_and_mirror.fm`。）渐进均值：连续两次 `setSamples(1)` 的 `renderPath` 得到样本 0 与 1 的均值（夹具 `011`）；`resetAccumulation` 后再一次则回到仅样本 0（夹具 `022`）。

### 7.3 材质：玻璃 / 金属 / 自发光 / 贴图

`MeshStandardMaterial` 在 M3 的 `color` / `roughness` / `metalness` 之外增加：

| 字段 | 默认 | 设置 |
|------|------|------|
| `transmission` | `0` | `setTransmission` |
| `ior` | `1.5` | `setIor` |
| `emissive` | 黑 | `setEmissive(Color)` 或 `setEmissive(hex)` |
| `emissiveIntensity` | `1` | `setEmissiveIntensity` |
| map | 无 | `setMap(tex)` |

着色时：`metal` / `rough` / `trans` 先 clamp 到 [0,1]；**若 `metal > 0` 则强制 `trans = 0`**（金属优先）。`rough == 0` 走完美镜面反射 / 折射（delta）；`rough > 0` 走粗糙直接光（Cook-Torrance）+ 一条余弦半球间接。自发光为 `emissive * emissiveIntensity`，击中表面时累加，**不会**被当作光源做 next-event 采样。

`MeshBasicMaterial` 不变：路径追踪命中后直接返回 `color` 并结束路径。

```
const glassMat: MeshStandardMaterial = new MeshStandardMaterial(new Color(1, 1, 1));
glassMat.setRoughness(0);
glassMat.setTransmission(1);
glassMat.setIor(1.5);

const mirrorMat: MeshStandardMaterial = new MeshStandardMaterial(new Color(1, 1, 1));
mirrorMat.setRoughness(0);
mirrorMat.setMetalness(1);
```

（摘自 `009_glass_and_mirror.fm`。）

### 7.4 `RectAreaLight` 与 `Texture`

```
new RectAreaLight()
new RectAreaLight(hex, intensity)
new RectAreaLight(hex, intensity, width, height)
new RectAreaLight(color, intensity, width, height)
```

矩形在局部 **XY** 平面、原点居中；发射方向为局部 **−Z**（与 `DirectionalLight` 朝向约定一致）。`width * height <= 0` 时该灯不贡献（不陷阱）。仅 `renderPath` 采样它。

```
const light: RectAreaLight = new RectAreaLight(0xffffff, 40, 0.5, 0.5);
light.position.set(0, 1.98, 0);
light.lookAt(0, 0, 0);
scene.add(light);
```

（摘自 Cornell 夹具 `008_cornell.fm`。）

`new Texture(path)` 在构造时读盘（相对进程工作目录）。须为规范子集 PNG（非交错、8 位 RGB 等）；失败立刻陷阱 **110**。`albedo = color * bilinear(tex, uv)`（无 sRGB 解码；clamp-to-edge）。`render` 忽略贴图。M4 无 `clearMap`。

```
const tex: Texture = new Texture("_ref/albedo.png");
mat.setMap(tex);
```

（摘自 `010_albedo_texture.fm`。）

### 7.5 线程、BVH、体积（用户须知）

- **`FARMOS_THREADS`**：`renderPath` 内部用 16×16 瓦片池。未设置 / 空 / 非法 / 越界 ⇒ **`W = 1`**（注意：与用户 `parallel` 未设置时用逻辑 CPU 数的默认**不同**）。合法 `W` 在 `1..256`，用户 `parallel` 与 `renderPath` 共用该值。像素结果**不得**依赖线程数或瓦片调度（1 与 4 应得到同一 PNG）。
- 从未执行 `parallel`、也从未调用 `renderPath` 的程序不应读取该变量、不应拉线程库。
- **BVH**：仅在走到 `renderPath` 时链接 / 构建（两级 median-split）；只调 `render` 的 hello 仍落在小体积预算内。高层预算（Windows x64 去符号 PE）：hello ≤ 20 KiB；玻璃+镜面 demo ≤ 300 KiB；Cornell 形 800×600 单次 `renderPath` 峰值工作集 ≤ 64 MiB。

### 7.6 并发与 `savePNG`

内部瓦片线程**不是**用户 `task`，对 M3.5 冲突检查不可见。用户规则不变：

- 用户任务里调 `savePNG` → 仍是 **E0805**；放在 join **之后**。
- 两个用户任务对**同一个** `Renderer` 调 `renderPath` → 按 M3.5 冲突（读场景、写显示缓冲与累加器）。

### 7.7 M4 陷阱

| 退出码 | 消息要点 | 何时 |
|--------|----------|------|
| 105 | use after dispose | 已 dispose 的渲染器 / 可见网格的几何或材质 |
| 107 | invalid renderer size | 尺寸非法或尚未成功 `setSize` |
| 108 | PNG write failed | `savePNG` I/O（同 M3） |
| 110 | texture load failed | `new Texture` 读不到支持的 PNG |
| 111 | invalid ior | 可见标准材质解析后 `transmission > 0` 且 `ior < 1` |
| 112 | invalid sample count | `samples < 1`（在 `renderPath` 时检查） |
| 113 | invalid bounce count | `maxBounces < 0` |

`setSamples` / `setMaxBounces` 本身不陷阱；非法值在 `renderPath` 时才炸。`ior == 1` 合法。金属因 `trans` 被置 0，坏 `ior` 不触发 111。退出码 **109** 仍保留未用。M4 **无**新编译诊断码。

## 8. M5 物理（`farmos:physics`）

规范见 `spec/M5-physics.md`。

### 8.1 模块边界

```
import { World, RigidBody, BODY_DYNAMIC, BODY_STATIC, BODY_KINEMATIC,
         SphereCollider, BoxCollider, PlaneCollider } from "farmos:physics";
```

`farmos:physics` **不**再导出 `farmos:scene` / `farmos:math`；需要场景或向量时自行导入。导出常量：`BODY_DYNAMIC`（0）、`BODY_STATIC`（1）、`BODY_KINEMATIC`（2）。类型均为 **class（引用）**。

### 8.2 `World` 与 `step`

```
new World()
setGravity(v: Vector3): void          // 默认 (0, -9.81, 0)；拷贝分量
setFixedTimeStep(dt: float): void     // 默认 1/60；dt<=0 在 step 时陷阱
add(body) / remove(body) / bodyCount()
step(): void
dispose(): void                       // 第二次为空操作
```

每次 `step()`（成功通过前置检查后）大致顺序：校验质量 / 碰撞体 → 积分 Dynamic → 宽相 + 窄相 → 确定性排序接触 → 顺序冲量求解（固定 **10** 次迭代、无 warm-start）→ 同步已链接的 `Object3D`。

积分是**半隐式（辛）Euler**，固定 `dt`，一次 `step` = 一个子步。物理**不**调用 `render` / `renderPath`，也不写 `scale`。

### 8.3 `RigidBody` 与碰撞体

```
new RigidBody(bodyType: int)   // 非法值按 Dynamic 处理，不陷阱
```

| 类型 | 质量 | 积分 | 响应 |
|------|------|------|------|
| Dynamic | 有限 `mass > 0` | 是 | 受冲量推动 |
| Static | 无限 | 否 | 不动；不受冲量 |
| Kinematic | 无限 | 否 | 用户每帧改位姿；可推 Dynamic，自己不被推 |

常用设置：`setMass` / `setRestitution` / `setFriction` / `setLinearDamping` / `setAngularDamping` / `setCollider` / `setObject` / `clearObject`。默认质量 1、恢复系数 0、摩擦 0.3。字段非法在 **`step` 时**才检查（设置器本身不陷阱）。

碰撞体：

- `new SphereCollider(radius)`
- `new BoxCollider(hx, hy, hz)` 或 `new BoxCollider(halfExtents: Vector3)`
- `new PlaneCollider()` — 无限平面，法线为体局部 **+Y** 经四元数转到世界；**仅**允许挂在 Static / Kinematic 上

### 8.4 材质合成与场景同步

接触上用户可见的合成：

- 恢复系数 `e = sqrt(clamp(eA,0,1) * clamp(eB,0,1))`（几何平均）
- 摩擦系数 `μ = sqrt(max(0,fA) * max(0,fB))`

`setObject(mesh)`：保存引用，并**拉取一次**网格的 `position` / `quaternion` 到刚体。之后每次 `step` 结束用**字段写入**把刚体位姿写回网格，并按 M3 规则同步 Euler；**不**写 `scale`。注意 M3 拷贝陷阱：不要先拷出 `Vector3` 再改副本。

### 8.5 最小弹跳示例

```
import { World, RigidBody, BODY_DYNAMIC, BODY_STATIC,
         SphereCollider, PlaneCollider } from "farmos:physics";

function main(): int {
  const world: World = new World();
  const floor: RigidBody = new RigidBody(BODY_STATIC);
  floor.setRestitution(1.0);
  floor.setFriction(0.0);
  floor.setCollider(new PlaneCollider());
  world.add(floor);

  const ball: RigidBody = new RigidBody(BODY_DYNAMIC);
  ball.setMass(1.0);
  ball.setRestitution(0.5);
  ball.setFriction(0.0);
  ball.setCollider(new SphereCollider(0.5));
  ball.position.set(0.0, 2.0, 0.0);
  world.add(ball);

  let i: int = 0;
  while (i < 600) {
    world.step();
    i = i + 1;
  }
  println(ball.position.y);
  return 0;
}
```

（摘自 `005_sphere_bounce_plane.fm`。堆叠见 `006_sphere_stack_600.fm` / `examples/05_stacking_bounce.fm`。）

### 8.6 并发与体积

`World.step` **单线程**；两个用户任务对同一 `World` 调 `step` / `add` / `remove` 等 → M3.5 冲突。未引用物理导出的程序不应链接物理单元（hello ≤ 20 KiB；demo 相对 scene-only 增量 ≤ 64 KiB）。

### 8.7 M5 陷阱

| 退出码 | 消息要点 | 何时 |
|--------|----------|------|
| 105 | use after dispose | 已 `dispose` 的 `World` 上再 `step` / 变更 API |
| 114 | invalid mass | Dynamic 且 `mass <= 0`（在 `step`） |
| 115 | invalid fixed timestep | `dt <= 0`（在 `step`） |
| 116 | invalid collider | Dynamic 挂 `PlaneCollider`；球 `radius <= 0`；盒任一半轴 `<= 0` |

## 9. M6 语言与文档硬化（用户可见部分）

规范见 `spec/M6-hardening.md`。下列是写程序时会碰到的改正与约定；CI 体积脚本细节从略。

### 9.1 `for` 里的 `continue` 会跑更新子句

```
let n: int = 0;
let i: int = 0;
for (i = 0; i < 5; i = i + 1) {
  if (i == 2) {
    continue;
  }
  n = n + 1;
}
```

（摘自 `001_for_continue_increments.fm`。）`continue` 跳过本轮体剩余部分后，**必须求值 `update` 子句**，再测 `condition`——与 C / TypeScript / Java 一致。`while` 里的 `continue` 不会凭空发明更新子句。

### 9.2 动态数组 `T[]`：赋值 / 传参 / 返回是别名

| 操作 | 语义 |
|------|------|
| `let b: T[] = a;`（`a` 为 `T[]`） | **别名**——同一缓冲 |
| 作参数传入 | 别名（`push` / 改元素对外可见） |
| 作返回值 | 别名 |
| 定长 `T[N]` 赋值 | **仍是拷贝**（值语义，不变） |
| 字面量 `let a: int[] = [1, 2];` | 新分配缓冲并拷入元素 |

```
let a: int[] = [1, 2];
let b: int[] = a;
push(b, 3);
println(len(a));   // 3
```

（摘自 `003_tarray_assign_aliases.fm`。）

### 9.3 运算符诊断：`operator !` / `operator =` → E0605

| 情况 | 码 |
|------|-----|
| `operator` 声明里写了**认识但不允许重载**的运算符（`!`、`=`、比较、逻辑、`[]` 等） | **E0605** `operator {op} is not overloadable` |
| 表达式位置上真正的非法 `!` / `=` 语法 | 仍是 **E0202** |
| 重载内置原始类型运算符 | **E0601**（不变） |

### 9.4 测试夹具：`run_approx` 默认 epsilon

写 / 读 `# kind: run_approx` 夹具时：若**省略** `# epsilon:`，线束默认绝对容差 **`1e-10`**。显式写出的 `# epsilon:` 优先。

### 9.5 文档、示例与体积门禁（简述）

- **英文规范文档**：`docs/language-reference.md`、`docs/getting-started.md`、`docs/porting-guide.md`。本 `使用手册.md` 是中文**信息性**指南，与英文并存，不以本手册覆盖 CI 策略细则。
- **示例程序**：`examples/01_hello.fm` … `examples/05_stacking_bounce.fm`（hello / 旋转立方体 / Cornell 路径追踪 / 玻璃+镜面 / 堆叠弹跳）。
- **体积与 DCE**：CI 强制 hello ≤ 20 KiB、场景 demo、路径追踪 demo、物理增量、以及“未执行 `parallel` 且未调用 `renderPath` 则不得拉线程启动符号”等检查。写业务代码时记住：不要无的 `import` 与未调用的 `renderPath` 不应把体积和线程库拖进来。
